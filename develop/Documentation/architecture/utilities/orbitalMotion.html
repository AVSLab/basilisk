void elem2rv(double mu, ClassicElements *elements, double *rVec, double *vVec)

Convert classical elements to a finite inertial Cartesian state.

Note

Inclination must satisfy 0 <= i <= pi. Ellipses use a > 0, e < 1; hyperbolas use a < 0, e > 1. No eccentricity tolerance selects a conic. Planar parabolas use e = 1, a = 0, rPeriap > 0 and true anomaly f.

Note

Rectilinear ellipses use e = 1, a > 0 and f = eccentric anomaly E, with outward motion for sin(E) > 0. Rectilinear hyperbolas use e = 1, a < 0 and f = signed hyperbolic anomaly H, outward for H > 0. Rectilinear parabolas use e = 1, a = rPeriap = 0, rmag > 0 and f = 0 for outward motion or f = pi for inward motion. For radial states the perifocal x axis is the outward radial ray; the plane about it is arbitrary. Extra fields are read only where required by these conventions.

Note

Invalid/nonfinite inputs, collisions, open-conic anomalies at or beyond infinity, and numerical overflow produce a diagnostic and all-NaN vectors.

Parameters:

  • mu – Positive gravitational parameter [L^3/s^2].

  • elements – Orbital elements, with distances in L and angles in radians.

  • rVec – [out] Inertial position vector [L].

  • vVec – [out] Inertial velocity vector [L/s].

void rv2elem(double mu, double *rVec, double *vVec, ClassicElements *elements)

Convert a Cartesian state to classical orbital elements.

Note

Inputs must be finite and use consistent distance units. Inclination is in [0, pi]; Omega, omega, and nonradial f are in [0, 2*pi), including hyperbolic f. Degenerate conics use the conventions documented in elem2rv().

Note

A dimensionless tolerance of 1e-12 selects singular-angle conventions. For e <= tolerance, omega = 0 and f is the argument of latitude. For sin(i) <= tolerance, Omega = 0 and i is set to 0 or pi; omega measures periapsis from the inertial x axis in the direction of orbital motion. If both conditions hold, f measures position from that axis in the direction of motion. Replacing unresolved directions introduces relative state errors on the order of the singularity tolerance.

Note

Parabolic energy and zero transverse velocity are detected within 8 machine epsilons of the local energy and speed scales, respectively. Radial states use a deterministic plane about the outward radial ray. Near zero energy, relative accuracy of a and state reconstruction from rounded a, e degrades as machine epsilon divided by abs(1-e). Nonradial finite-energy states whose eccentricity rounds to one or the wrong side of one cannot be encoded consistently. These, invalid inputs and numerical overflow produce a diagnostic and all-NaN elements.

Parameters:

  • mu – Positive gravitational parameter [L^3/s^2].

  • rVec – Nonzero inertial position vector [L].

  • vVec – Inertial velocity vector [L/s].

  • elements – [out] Orbital elements, with distances in L and angles in radians.

void clMeanOscMapChecked(double req, double J2, ClassicElements *elements, ClassicElements *elements_p, double sgn)

Apply the first-order J2 mean/osculating element mapping.

Note

Follows Appendix F of Analytical Mechanics of Space Systems, Schaub and Junkins, fourth edition. Inputs must be finite and elliptic with inclination in [0, pi], away from the critical inclinations where 1 - 5*cos(i)^2 = 0. The perturbation must be small; opposite mappings leave second-order J2 errors.

Note

Both equatorial limits are supported. Whole revolutions in true anomaly do not affect the mapped Cartesian state; output angles need not retain input revolution counts. J2 = 0 copies the six classical elements exactly. Only a, e, i, Omega, omega and f are written; auxiliary fields are unchanged. Input and output may alias.

Note

Requires req > 0 and sgn = +/-1. For nonzero J2, rejects |1 - 5*cos(i)^2| <= sqrt(DBL_EPSILON) and nonphysical or nonfinite mapped elements. This numerical guard does not establish perturbation-model accuracy. Invalid inputs or results produce a diagnostic and six NaN classical elements.

Parameters:

  • req – Equatorial radius, in the same length unit as elements->a.

  • J2 – Dimensionless second zonal harmonic coefficient.

  • elements – Input classical elements, with angles in radians.

  • elements_p – Output classical elements, with the same units as the input.

  • sgn – +1 for mean to osculating, -1 for osculating to mean.

void atmosphericDrag(double Cd, double A, double m, double *rvec, double *vvec, double *advec)

Estimate Earth’s atmospheric drag acceleration opposite the supplied velocity.

Note

Assumes an atmosphere at rest in the input inertial frame; no rotation or wind correction is applied. Uses atmosphericDensity(), whose fit is valid from 100 to 1000 km; positive altitudes below this range are extrapolated, and above 1000 km the existing exponential tail is retained, without a hard cutoff.

Note

Zero speed, area, coefficient, or computed density gives zero acceleration after input validation. Invalid inputs, unrepresentable norms, or acceleration overflow produce a diagnostic and three NaNs. Acceleration underflow is allowed. The output may alias either input vector; all arrays must hold three doubles.

Parameters:

  • Cd – Finite, nonnegative drag coefficient [-].

  • A – Finite, nonnegative projected area [m^2].

  • m – Finite, positive spacecraft mass [kg].

  • rvec – Finite inertial position three-vector [km], above Earth’s equatorial radius.

  • vvec – Finite inertial velocity three-vector [km/s].

  • advec – [out] Drag acceleration in the input frame [km/s^2].

void jPerturbForPlanet(double *rvec, int num, double *ajtot, CelestialObject_t planetID)

Compute a selected body’s zonal perturbation acceleration.

Note

Earth includes J2 through J6. Mercury, Venus, Moon, Mars, Jupiter, Saturn, Uranus and Neptune include J2 only. Sun and Pluto use a zero-zonal approximation and return a zero vector. Phobos and Deimos are unsupported. These approximations omit central gravity, tesseral terms and other forces.

Note

The external gravity expansion is intended for positions outside the body’s reference radius; the surface boundary is not enforced. All inputs are validated even for zero-zonal models. Invalid inputs or nonfinite results produce a diagnostic and an all-NaN vector. Input/output arrays may alias.

Parameters:

  • rvec – Finite, nonzero planet-centered position [km], with z along the spin axis.

  • num – Maximum included degree, from 2 through 6 (inclusive).

  • ajtot – [out] Perturbation acceleration in the input frame [km/s^2].

  • planetID – Body whose coefficients are used; unsupported identifiers are errors.

void solarRad(double A, double m, double *sunvec, double *arvec)

Purpose: Computes the inertial solar radiation force vectors based on cross-sectional Area and mass of the spacecraft and the position vector of the planet to the sun. Note: It is assumed that the solar radiation pressure decreases quadratically with distance from sun (in AU)

Solar Radiation Equations obtained from Earth Space and Planets Journal Vol. 51, 1999 pp. 979-986 Inputs: A = Cross-sectional area of the spacecraft that is facing the sun in m^2. m = The mass of the spacecraft in kg. sunvec = Position vector to the Sun in units of AU. Earth has a distance of 1 AU. Outputs: arvec = The inertial acceleration vector due to the effects of Solar Radiation pressure in km/sec^2. The vector components of the output are the same as the vector components of the sunvec input vector.
