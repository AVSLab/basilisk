Executive Summary

This module is reads in a desired attitude control torque vector and maps it onto a set of thrusters.

The module works for both on-pulsing (nominal thruster state is off such as with RCS thrusters) and off-pulsing (nominal thruster state in such as with DV thrusters). More information can be found in the PDF Description.

Module Assumptions and Limitations

The variable controlAxes_B holds up to three orthonormal control axes \(\hat{\mathbf{c}}_j\), stored row by row in body frame components as the matrix \([C]\). Unused rows are zero-padded. Reset() normalizes each axis, and logs a BSK_WARNING if any two axes are not orthogonal, as the math below then no longer holds.

Let \({}^{\cal B}\mathbf{L}_{\mathrm{cmd}}\) be the input torque request and \(\mathbf{F}_{\mathrm{nom}}\) the nominal thruster forces. For on-pulsing (thrForceSign = +1), \(\mathbf{F}_{\mathrm{nom}}\) is zero and the commands \(\mathbf{F}\) are nonnegative forces. For off-pulsing (thrForceSign = -1), \(\mathbf{F}_{\mathrm{nom}} = \mathbf{F}_{\max}\) and \(\mathbf{F}\) represents nonpositive changes from those nominal forces: a zero command leaves a thruster fully on, while \(F_i = -F_{\max,i}\) requests that it remain off for the control period. The allocator subtracts the nominal thruster torque before projecting the request:

\[{}^{\cal B}\mathbf{L}_r = {}^{\cal B}\mathbf{L}_{\mathrm{cmd}} - [D]\mathbf{F}_{\mathrm{nom}}.\]

This adjusted target is reduced onto the control axes, written in body frame components, as

\[{}^{\cal B}\bar{\mathbf{L}}_r = [C]^T [C] \, {}^{\cal B}\mathbf{L}_r\]

The allocator attempts to find thruster forces \(\mathbf{F}\) satisfying \([C][D]\mathbf{F} = [C]\,{}^{\cal B}\mathbf{L}_r\). For off-pulsing, positive commands no larger than 64 * DBL_EPSILON times the largest absolute command are clamped to zero. The original two-stage allocation is otherwise retained if every command is nonpositive. A larger positive command triggers a nonnegative least-squares fallback over all thrusters:

\[\min_{\mathbf{u}\geq 0}\left\|-[C][D]\mathbf{u}-[C]\,{}^{\cal B}\mathbf{L}_r\right\|_2^2, \qquad \mathbf{F}=-\mathbf{u}.\]

Among allocations with the best achievable controlled torque, a second step minimizes \(\|\mathbf{u}\|_2\). This gives a unique minimum-force solution, including for proportional thruster columns, and avoids selecting a large weak-thruster command when smaller commands can produce the same torque. The solver does not impose thrust-magnitude limits. Both steps use deterministic active-set methods that add and release thrusters and solve their subproblems using reorthogonalized QR. The first step needs at most three independent thruster columns; the second can distribute force over all thrusters. A row-space projection of the current feasible forces gives the second step’s minimum-norm trial while preserving its achieved torque. This avoids cancellation that can cause cycling at zero-force boundaries. One common map normalization preserves relative torque authority, and target normalization makes the numerical tests relative to the problem scale. Gradient comparisons use a tolerance to handle numerical ties. The two steps share a limit of 6 * MAX_EFF_CNT active-set steps (216 with the current 36-thruster limit). If they cannot converge within that budget or numerical rank prevents further progress, it logs BSK_WARNING and retains its last nonpositive allocation. All allocations then use the saturation policy below. Existing singular-matrix handling in the two-stage allocator is unchanged; an all-zero allocation does not trigger sign repair.

The magnitudes of the commanded force changes \(\mathbf{F}\) can exceed the individual thruster limits \(F_{\max,i}\). The angle calculation uses the saturation-clipped commands \(\mathbf{F}_{\mathrm{clip}}\) and their torque contribution:

\[F_{\mathrm{clip},i} = \min\left(F_{\max,i}, \max\left(-F_{\max,i}, F_i\right)\right), \qquad {}^{\cal B}\boldsymbol{\tau} = [D]\mathbf{F}_{\mathrm{clip}}.\]

The corresponding ideal average net thruster torque is \({}^{\cal B}\boldsymbol{\tau}_{\mathrm{net}} = [D](\mathbf{F}_{\mathrm{nom}} + \mathbf{F}_{\mathrm{clip}})\). In off-pulsing mode, \(\boldsymbol{\tau}\) is the change from nominal torque, and differs from \(\boldsymbol{\tau}_{\mathrm{net}}\) when the nominal thrust produces a nonzero torque.

The output outTorqAngErr is the angle between this torque contribution and the reduced adjusted target \({}^{\cal B}\bar{\mathbf{L}}_r\), both in body frame components:

\[\theta = \arccos \left( \frac{\boldsymbol{\tau} \cdot \bar{\mathbf{L}}_r}{|\boldsymbol{\tau}| \, |\bar{\mathbf{L}}_r|} \right)\]

This angle is invariant under reordering the control axes or choosing another orthonormal basis for the same controlled subspace. Changing the controlled subspace can change the angle and force solution.

If this angle is larger than angErrThresh [rad] and any commanded force exceeds its limit, all commanded forces are scaled by the same positive factor to satisfy every thruster limit. The resulting torque contribution preserves the direction of the unscaled contribution \([D]\mathbf{F}\). It aligns with \(\bar{\mathbf{L}}_r\) only if that unscaled torque was already aligned; residual torque outside the controlled subspace is also scaled and can leave a nonzero angle error. In off-pulsing mode, these direction statements concern the change from nominal torque; the net torque also includes the unchanged nominal contribution \([D]\mathbf{F}_{\max}\). The module recomputes outTorqAngErr after scaling. If the angle is at or below the threshold, the output force commands can remain above their limits even though the angle calculation uses clipped forces. The default value of angErrThresh is 0 rad. Setting it to a value larger than \(\pi\) rad disables scaling.

Thruster locations, force directions, and maximum thrust values are read from thrConfigInMsg during Reset() and remain cached until the next reset. The spacecraft center of mass is read from vehConfigInMsg on every update, and the module recomputes the thruster moment arms using the current CoM_B. Center-of-mass changes therefore do not require a reset.
