C++ Module: constrainedAttitudeManeuver

Auxiliary Files

  • Unit tests

Example usage

  • scenarioAttitudeConstrainedManeuver

Executive Summary

This module searches a grid of spacecraft attitudes for a path subject to keep-in and keep-out pointing cones. It fits a spline to the selected waypoints and publishes an attitude reference for a tracking controller. A fitted reference can cross a cone boundary even when every waypoint satisfies the pointing constraints.

Module Assumptions and Limitations

The module, in its current form, allows to only include one keep-out and one keep-in celestial object(s). Multiple boresights (up to 10) can be specified as either keep-in or keep-out body directions. Each category has ten slots. Appending beyond that limit raises an error. Both append methods normalize finite, nonzero body-frame directions. Cone half-angles are measured from the boresight and must be in \([0, \pi]\) radians, including both endpoints. Both cone types include their rim within angular roundoff. A point on the rim satisfies a keep-in constraint and violates a keep-out constraint. When setting the public boresight arrays directly, supply unit vectors. The planner checks the active entries when reading inputs and when building the grid. The keep-out constraint is considered respected when all the keep-out body-fixed boresights are outside of the keep-out zone simultaneously. The keep-in constraint is satisfied when at least one keep-in body-fixed direction is inside the keep-in zone. Each category is active only when it has a boresight and its celestial-body message is linked. An active category requires a written message at reset and a finite, nonzero separation between the spacecraft and the celestial body. Inertial cone axes supplied directly must also be finite and nonzero.

GenerateGrid() reclassifies both endpoint attitudes using the current boresights and the last-read celestial-body directions. Call ReadInputs() before a direct rebuild after enabling or disabling a category, after replacing a source even if it stays linked, or to use updated spacecraft or celestial-body positions. Reading inputs invalidates the previous grid and reference. effortBasedAStar(), spline(), and effortEvaluation() use cached spacecraft inputs and require a successful ReadInputs(). If a read fails, correct the input and read again. Reset() refreshes the inputs automatically.

A target attitude that violates a pointing constraint causes planning to fail. An initially noncompliant attitude raises a warning so the planner can search for a path out of the violation. The remaining waypoints satisfy the cones evaluated with the directions read at reset. The User Guide describes how these checks apply to the fitted reference.

The supported grid refinement range is 2 <= N <= 20. With the no-argument constructor, set N before building the grid. Its initial value is zero (unset). Grid generation validates the current value, including changes made after construction, and raises an error outside this range. The planner also raises an error rather than overflowing its fixed storage if a node would have more than 52 neighbors. Search and path storage grow dynamically with the graph. NodeList.N is the read-only active node count in Python. Use append(), pop(), and clear() to change the entries. Python append() requires a Python-owned node. The list retains it until its last entry is removed. The search sets each node’s predecessor, backPointer, which is read-only in Python. For C++ callers, NodeList::list is now a std::vector<Node*>. Use the list methods to populate it. Indexed access to active entries is unchanged; use list.data() where a raw pointer to the entries is required. Do not retain pointers to the entry storage across list changes. You can assign a path containing only Python-owned nodes to another planner. A generated path borrows nodes from its planner’s grid, so copying it raises an error. Use returnPathCoord() to copy its coordinates. NodeList.pop() and NodeList.swap() require indices within the active list. returnPathCoord() returns 1000 for an invalid waypoint index or coordinate axis.

When grid generation clears the previous grid and path, it also resets the endpoint keys (keyS and keyG). Each component is invalidGridIndex from construction until an endpoint pair is selected, and again if a rebuild finds no constraint-free node. In that case, initialization raises an error before graph search. This means the sampled grid cannot support planning; it does not prove that no continuous maneuver exists. Review the constraints or choose another supported refinement level. Direct calls to AStar() and effortBasedAStar() require a successful grid build. After changing N, call GenerateGrid() again before running either search directly. Reset() rebuilds the grid automatically.

Rebuilding the grid or starting a search discards previously prepared waypoints and fitted output. The planner also discards them when a NodeList method or assignment to path changes the node sequence. After a direct search or path-list edit, call pathHandle() and then spline() to fit the new path. Changing a node’s sigma_BN in place bypasses the list, so call both methods before querying that path. When editing Input directly, supply one value per waypoint in each coordinate array and in any explicit time array. Supply elapsed seconds starting at zero, with finite, strictly increasing times. Distance-based timing requires distinct consecutive waypoints. A least-squares fit reserves one control point for each endpoint position and prescribed derivative. The remaining control points cannot outnumber the interior waypoints. Each prescribed endpoint acceleration requires velocity at that same endpoint. If weights are supplied, provide one per waypoint. Interior weights must be finite and nonnegative. A zero interior weight omits that waypoint’s residual from the least-squares objective. The remaining weighted waypoints must still determine all free control points. Output.getData() and Output.getStates() raise an error if the fit has been cleared. computeTorque() and computeTorqueNorm() require an index in the current fitted samples. effortEvaluation() requires at least two time samples and one value per time sample in each attitude, first-derivative, and second-derivative component. The cached pathCost is NaN until Reset() accepts a fitted reference.

The start and goal must represent different physical attitudes, including when expressed in different MRP sets. They must also map to different sampled attitudes. Antipodal nodes on the MRP unit sphere represent the same sampled attitude. If the endpoints map to the same sampled attitude, initialization raises an error before graph search. A finer grid may separate distinct but nearby endpoints.

Even when both endpoints are free, the sampled grid can be disconnected. Both search methods raise an error if they exhaust the reachable nodes. The default distance search also raises an error after 4 * N * N expansions, and the effort search after 100 expansions, unless the goal is selected. A search that reaches its limit may still have unexplored nodes. The optional shortest-path search runs until it selects the goal or exhausts the reachable graph. Starting a reset, rebuilding the grid, running either search, preparing the waypoints, or refitting the spline invalidates the previous reference. Only a successful reset enables UpdateState() to write either attitude output. The maneuver starts at the simulation time passed to that reset. Output messages retain absolute simulation timestamps.

Detailed Module Description

A detailed explanation of the method implemented in this module can be found in R. Calaon and H. Schaub, “Constrained Attitude Maneuvering via Modified-Rodrigues-Parameter-Based Motion Planning Algorithms”. To summarize, this module builds a 3D grid in MRP space, whose density is regulated by the input parameter N. Each grid node corresponds to an attitude. An undirected graph is built with all the nodes that are constraint compliant. Two nodes are added to the graph:

  • startNode whose coordinates \(\sigma_{BN,S}\) are the spacecraft attitude from scStateInMsg.

  • goalNode whose coordinates \(\sigma_{BN,G}\) correspond to the desired target attitude at the end of the maneuver.

The distance-based search ranks paths by their accumulated MRP distance plus an estimate of the distance to the goal. By default, the estimate can exceed the remaining graph distance, so the selected path can be longer than the shortest grid path. Setting useShortestPath = True selects the consistent lower bound \(h = \theta/4\), where \(\theta \in [0, \pi]\) is the principal relative rotation angle to the goal in radians. For any edge, its MRP distance \(d(u,v)\) satisfies \(\theta(u,v) \leq 4d(u,v)\): along a straight segment between either pair of MRP representations, \(\|\boldsymbol{\omega}\| = 4\|\dot{\boldsymbol{\sigma}}\|/(1+\|\boldsymbol{\sigma}\|^2)\). Together with the triangle inequality for rotation angles, this gives \(h(u) \leq d(u,v) + h(v)\). The optional search therefore expands each reachable node at most once and returns a path with minimum accumulated edge distance when it selects the goal.

The effort-based search ranks candidate splines by the integral of the control torque norm. It keeps one predecessor per node even though the effort depends on the entire path, so another feasible path can have lower effort.

The module fits the selected path using BSpline. When the path contains only the start and goal waypoints, both fitting modes use a cubic determined by the endpoint attitudes and rates. When refitting with spline(), prescribing an MRP second derivative at one endpoint with Input.setXDDot_0() or Input.setXDDot_N() gives a quartic. Prescribing both gives a quintic. Longer paths use a quartic spline. Endpoint angular rates are converted using the MRP set selected for each waypoint. The planner selects the MRP sequence with the smallest peak norm over the entire short rotation between each pair of waypoints. At a relative rotation of 180 degrees both directions are eligible. A tie between starting sets within roundoff favors a principal-set start. If every sequence reaches an MRP singularity, split the maneuver.

The planner also bounds the total fitted angular travel on each waypoint interval, including reversals. It accepts a fit only when this bound is less than the short waypoint separation plus one full revolution. A conservative bound can reject a fit near this limit. If this occurs, split the maneuver and replan. The effort-based search skips such candidate paths, as well as candidates with invalid waypoint intervals or nonfinite control effort. A nonfinite final effort causes reset to raise an error.

Note that this module does not implement the constant angular rate norm routine described in R. Calaon and H. Schaub. The attitude, rates and accelerations provided to the Attitude Reference Message are those obtained directly from the BSpline interpolation.

User Guide

To request a shortest path on the generated graph, configure the planner before reset:

planner.costFcnType = 0
planner.useShortestPath = True

useShortestPath defaults to False and also applies to direct AStar() calls. It has no effect on effortBasedAStar() or costFcnType = 1. The optional mode shares the default distance search’s graph and edge costs, but can explore substantially more nodes. It uses a priority queue and has no expansion cap; allow additional planning time and memory, especially at higher refinement. expandedNodeCount reports the last search’s expansions, excluding the selected goal, and is read-only in Python. Building a new grid resets the count.

The guarantee is limited to the sum of MRP edge distances on the generated graph, including its endpoint connections and shadow-set links. Equally short paths can have different waypoints. It does not guarantee the shortest continuous maneuver, minimum control effort, or continuous cone clearance along the fitted reference. pathCost continues to report the fitted reference’s control effort in N m s, not grid distance. An unreachable goal means that the generated graph has no route; a continuous maneuver may still exist.

A maneuver can start at any simulation time. Waypoint times are elapsed seconds from the planner’s most recent successful reset. For example, after a reset at 3600 s, waypoint times of 0 s and 5 s correspond to simulation times of 3600 s and 3605 s. The attitude reference messages carry absolute simulation timestamps.

When refitting with spline(), supply finite attitude components at every waypoint, including zero-weight waypoints. The planner uses each attitude to bound angular travel. Only the standalone BSpline.approximate() accepts missing coordinates at zero-weight interior waypoints, and only when you supply explicit waypoint times.

This example slews from rest at the identity attitude about the inertial z-axis. The body x-axis must stay outside a 20-degree cone around a fixed celestial direction. Write the state, inertia, and celestial-body messages before initialization so the planner can read them at reset. The recorder runs after the planner on the same task.

import numpy as np
from Basilisk.architecture import messaging
from Basilisk.fswAlgorithms import constrainedAttitudeManeuver
from Basilisk.utilities import SimulationBaseClass, macros

sim = SimulationBaseClass.SimBaseClass()
process = sim.CreateNewProcess("process")
process.addTask(sim.CreateNewTask("guidance", macros.sec2nano(1.0)))  # [s]

state = messaging.SCStatesMsg().write(messaging.SCStatesMsgPayload())
vehicle = messaging.VehicleConfigMsgPayload()
vehicle.ISCPntB_B = [10, 0, 0, 0, 12, 0, 0, 0, 14]  # [kg m^2]
config = messaging.VehicleConfigMsg().write(vehicle)
body = messaging.SpicePlanetStateMsgPayload()
body.PositionVector = [0, 0, 1e8]  # [m] same inertial frame and origin as the spacecraft position
body_state = messaging.SpicePlanetStateMsg().write(body)

planner = constrainedAttitudeManeuver.ConstrainedAttitudeManeuver(5)
planner.sigma_BN_goal = [0, 0, 0.5]  # MRPs [-]
planner.avgOmega = 0.04  # [rad/s]
planner.costFcnType = 0  # distance-based search
planner.BSplineType = 0  # interpolation
planner.scStateInMsg.subscribeTo(state)
planner.vehicleConfigInMsg.subscribeTo(config)
planner.appendKeepOutDirection([1, 0, 0], np.deg2rad(20))  # [-], [rad]
planner.keepOutCelBodyInMsg.subscribeTo(body_state)

recorder = planner.attRefOutMsg.recorder()
sim.AddModelToTask("guidance", planner, ModelPriority=1)
sim.AddModelToTask("guidance", recorder)
sim.InitializeSimulation()
sim.ConfigureStopTime(macros.sec2nano(60.0))  # [s]
sim.ExecuteSimulation()
np.testing.assert_allclose(recorder.sigma_RN[-1], planner.sigma_BN_goal, atol=1e-12)

Cone compliance. The planner holds each celestial direction fixed at its reset value. Interpolation passes through the selected attitudes and can cross a cone boundary between waypoints. Least-squares approximation can also miss an interior waypoint at its assigned time. Increasing N changes the sampled path and computational cost. No grid refinement guarantees continuous clearance. If the maneuver requires it, verify clearance along the full fitted reference using the expected time-varying celestial directions and a margin for tracking error.

See scenarioAttitudeConstrainedManeuver for a closed-loop spacecraft example with both cone types. Its optional compareSearchModes=True run with attitude case 4 overlays the default and shortest grid paths and compares their accumulated MRP edge distances and node expansions. The example then simulates the shortest-path reference; existing calls retain effort-based planning.

Module Parameters

Parameter

Description

N

grid refinement level, an integer from 2 through 20 inclusive

sigma_BN_goal

Required finite goal attitude in MRPs. In Python, assign a sequence of exactly three components. Zero MRPs specify the identity attitude.

Desired body-frame angular rate at the goal in rad/s. Defaults to zero.

Required finite, positive timing parameter in rad/s. The planner sets each waypoint interval to four times the MRP distance between its endpoints divided by avgOmega. The physical mean and peak angular speeds depend on the fitted trajectory.

Optional distance-search flag, initially False. Set to True to minimize total MRP edge distance on the generated graph using the rotation-angle lower bound and no expansion cap. Ignored in effort mode.
