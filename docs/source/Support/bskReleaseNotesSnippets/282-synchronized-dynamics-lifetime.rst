- ``syncDynamicsIntegration()`` now retains Python secondary objects and removes native synchronization links when either object is destroyed. Surviving secondaries can integrate independently again, repeated connections are a no-op, and invalid null, self, nested, or competing-primary connections raise ``BasiliskError``. Python calls must use the owning primary object; borrowed primary proxies are rejected before changing connections. See :ref:`bskSynchronizedDynamicsLifetime`. Compiled extensions using ``DynamicObject`` must be rebuilt against the updated SDK extension ABI version 3 layouts.
