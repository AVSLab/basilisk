- :ref:`lambertSolver` now raises ``BasiliskError`` for unknown ``solverMethod`` values before solving. ``LambertProblemMsgPayload.solverMethod`` is an ``int`` validated before conversion to the internal enum; C++ callers assigning this field to a ``SolverMethod`` variable must validate and explicitly cast it. Existing ``IZZO`` (0, the default) and ``GOODING`` (1) selections and planner APIs are unchanged, and corrected requests can recover without resetting the solver.
