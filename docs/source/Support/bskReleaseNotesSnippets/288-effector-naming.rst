- Added opt-in manager-local automatic effector names through ``dynManager.useManagerLocalEffectorNames``, recommended for new ``Spacecraft`` scripts. Names are resolved during initialization, avoiding constructor-counter interference between simulations and detecting collisions across effector types. Legacy naming remains the default for compatibility; see :ref:`effectorNaming`.
- Preserved optional custom names and Python name-attribute syntax for migrated effectors; C++ callers use the corresponding name getters and setters. Reaction-wheel and VSCMG arrays now support manager-local naming, including multiple arrays in one spacecraft.
- Deprecated legacy automatic effector naming for removal on September 14, 2027. Python reports one ``BSKDeprecationWarning`` per dynamics manager when a built-in effector registers an automatic legacy name, with the opt-in flag and migration link. On or after the removal date it becomes ``BSKUrgentDeprecationWarning``. Scheduled managers report after initialization or task reset, allowing warning-as-error handling outside C++ callbacks. Simulations initialized inside these callbacks defer warnings until the outer call completes; concurrent independent calls report separately. Explicit names alone and manager-local naming do not trigger this warning; legacy naming remains the default during the transition.
- Added an optional ``stacklevel`` argument to ``deprecated.deprecationWarn()`` so additional wrapper layers can attribute warnings to the calling script.
- Updated example and test callbacks to read generated names when used, added :ref:`scenarioEffectorNaming`, and tested representative scenarios under both naming policies. Deprecated ``SpacecraftSystem`` remains legacy-only and preserves its state-name prefixes across repeated initialization.
