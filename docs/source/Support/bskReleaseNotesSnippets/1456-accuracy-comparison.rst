- Added :ref:`accuracyComparison`, a rough comparison of Basilisk orbit propagation against GMAT and Orekit for zonal and tesseral gravity up to degree and order 70, Sun and Moon third-body forces, solar radiation pressure, and exponential-atmosphere drag, in LEO, sun-synchronous, Molniya, GTO, and GEO orbits at several epochs, all in the ICRF axes. The exponential-atmosphere drag is compared with both tools, and the faceted drag and solar radiation pressure of a box spacecraft with a fixed and with a spinning attitude are compared with Orekit. The scripts that generate the GMAT and Orekit reference ephemerides, which also write a manifest with the case configuration, frame, tool versions and data checksums that is validated before the comparison, and that run the comparison, which also compare the altitude and density of the three exponential atmospheres at a set of probe points before any propagation, are in ``benchmarks/accuracyComparison``, and the page explains how to reproduce the results.
- Fixed the gravity effector extrapolating the planet orientation with a first-order update of the matrix elements, which is not orthonormal. The orientation is now advanced as a rotation about the planet angular velocity. Before, a SPICE-driven planet distorted even a point-mass field by a relative error of order :math:`(\omega\,\Delta t)^2` of the time since the planet message was written. The ``J20002Pfix`` and ``J20002Pfix_dot`` state properties of the gravity bodies were also stored transposed after each gravity evaluation, as :math:`[NP]` instead of the documented :math:`[PN]`. They now hold :math:`[PN]` and :math:`[\dot{PN}]` as documented, which matters to code that reads these properties.
- Added ``setExtrapolateScStateToStepMidpoint()`` and ``getExtrapolateScStateToStepMidpoint()`` to :ref:`atmosphereBase` (including :ref:`msisAtmosphere`, :ref:`exponentialAtmosphere`, and :ref:`tabularAtmosphere`), :ref:`windBase`, :ref:`magneticFieldBase`, :ref:`eclipse`, and :ref:`solarFlux`. These modules evaluate the spacecraft state of the previous step because they run before the spacecraft. When the extrapolation is enabled, the spacecraft position is advanced to the middle of the interval the next spacecraft update integrates. This removes a step-size dependent error. The planet (or sun) position and orientation are moved to the same epoch, so a translating planet does not bias the relative position. Stale messages are not extrapolated. The extrapolation is disabled by default and requires that the module is updated with the same task period as the spacecraft. The extrapolation starts once two spacecraft write times show an interval equal to the module update interval, so the first updates are not extrapolated, and during them the planet is moved back to the epoch of the spacecraft state to keep the relative geometry consistent. If the spacecraft is faster or slower than the module, nothing is extrapolated, and a warning is logged when a spacecraft message is found not to have been written at the previous module update. A mismatch is not always detectable, since a message written at the current module update is used as written, but a message that is not the output of the previous module update is never extrapolated. With several spacecraft the extrapolation is applied to all of them and to the planets, or to none.
- Added ``setPlanetPolarRadius()`` and ``getPlanetPolarRadius()`` to :ref:`atmosphereBase` to compute the altitude, and the latitude in :ref:`msisAtmosphere`, above an oblate ellipsoid. The default remains a sphere.
- Added ``setUseApparentSolarTime()`` and ``getUseApparentSolarTime()`` to :ref:`msisAtmosphere` to add the equation of time to the local solar time input of NRLMSISE-00. The default remains the mean solar time.
- Added ``setUseApHistory()`` and ``getUseApHistory()`` to :ref:`msisAtmosphere` to make NRLMSISE-00 use the 3-hour Ap history of the space weather messages (switch 9 set to -1) instead of the daily Ap, which follows a geomagnetic storm more closely. The default remains the daily Ap.
- Fixed ``PCPF2LLA()`` returning an altitude that was wrong for a position exactly at a pole of an oblate planet, where the equatorial component is zero.
- Fixed :ref:`msisAtmosphere`, :ref:`windBase`, :ref:`magneticFieldBase`, and :ref:`magneticFieldWMM` converting the UTC epoch with ``mktime``, which uses the time zone of the computer. On a computer in a time zone with daylight saving time, the local solar time of :ref:`msisAtmosphere` was one hour wrong after a simulation crossed a daylight saving transition. The epoch is now converted as UTC with the new ``architecture/utilities/utcTime.h``.
- Changed :ref:`facetSRPDynamicEffector` to use the solar flux ``SOLAR_FLUX_EARTH`` of 1361 W/m\ :sup:`2` at 1 AU, as :ref:`radiationPressure` does, instead of 1368 W/m\ :sup:`2`. The facet SRP force is 0.5% smaller than before.
